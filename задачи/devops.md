## СХЕМА ПОИСКА ПО СМЫСЛУ — читать перед работой (владелец подтвердил 2026-07-30)

Путь запроса читателя, на примере французского:

```
«trous noirs qui s'évaporent»                      ← читатель, любой язык сайта
   1) перевод запроса → EN (flash, ~$0.0001)        «evaporating black holes»
   2) вектор из EN-запроса (bge-m3)
   3) поиск в ЕДИНСТВЕННОМ индексе                  весь индекс построен из EN-текстов
   4) топ: id + английские заголовки
   5) перевод результатов → язык читателя           flash на лету, КЭШ в KV (id+lang):
                                                    вторая выдача той же пары бесплатна
клик → статья есть на языке? открылась.
       нет? честная заглушка + «перевести сейчас» → очередь → минута
```

Три «почему», одинаковые для всех:
- **индекс ОДИН, английский** — en есть у всех документов (наши статьи И будущие чужие
  абстракты), научные термины в en каноничны → вектор точнее;
- **переводим запрос, а не индекс** — запрос стоит сотые цента; 50 индексов под
  50 языков — в 50 раз дороже и разъезжаются по качеству;
- **результат переводится на лету с кэшем** — читатель всегда видит свой язык,
  популярное переводится один раз на язык навсегда.

bge-m3 мультиязычна и иногда поймёт запрос без шага 1 — но базовый путь С ПЕРЕВОДОМ
(надёжнее терминология); прямой путь — оптимизация потом, по замеру качества, не сейчас.

## 0. Авторизация и учёт токенов — ВПЕРЁД ВСЕГО ОСТАЛЬНОГО

Решение владельца 2026-07-29: ни векторный поиск, ни помощник в курсе не открываются,
пока нет учёта расхода.

Что нужно:

- **Вход** — два пути на выбор читателя (решение владельца 2026-07-30):
  **через Google** (OAuth, один клик — и барьер ботам) и почта+одноразовый код
  (для тех, кто без Google). Паролей не храним никогда.
- **Cloudflare Turnstile** на вход и на будущую кнопку «хочу статью» — их бесплатная
  замена капчи, невидимая для человека, стена для скриптов. Владелец прямо просил
  защиту от ботов — это она.
- **Счётчик на пользователя** в KV: потрачено за сутки, потрачено за неделю.
- **Бесплатная норма** — число задаётся настройкой, а не зашито в код: мы будем его крутить.
- **Читателю видно, сколько осталось.** Не «превышен лимит» постфактум, а полоска
  «осталось 40 из 50 на сегодня» до того, как он начал.
- **Общий потолок на проект** — предохранитель поверх пользовательских: если что-то пойдёт
  не так, счёт не должен уходить в тысячи.

**Зачем так строго.** Всё, что дальше в этом файле, стоит денег за каждый запрос. Пока
бесплатных лимитов Cloudflare хватает, но именно поэтому легко проглядеть момент, когда
перестанет хватать. Счётчик, поставленный до запуска, — это единственный способ узнать
о проблеме раньше счёта.

**Готово, когда:** пользователь входит, видит свою норму и остаток, при исчерпании получает
понятное объяснение и предложение подождать до завтра. В журнале видно суточный расход
по проекту целиком.

## 1а. Векторный поиск (сделано частично — индекс построен)

Приоритет владельца: даёт и заметный прирост поиску, и основу для всего остального.

- Эмбеддинги статей — ИЗ АНГЛИЙСКОЙ версии (заголовок+аннотация en), это
  зафиксировано владельцем 2026-07-30: английский каноничен для научных терминов,
  есть у всех документов, и вектор из него точнее. Не из русского оригинала
  и не из переводов. Запросы на других языках приводит схема ML (гибрид).
- Индекс в Vectorize
- Worker `/api/search`: запрос → вектор → список статей

**Зачем.** Сейчас поиск ищет совпадение слов. В науке одно и то же называют по-разному
у разных авторов, поэтому совпадение слов — плохая мерка. По смыслу читатель найдёт то,
чего искал, даже не зная нашего термина.

**Что это открывает дальше** (не делать сразу, но закладывать): связи между статьями,
тегами, законами и учёными можно строить **по векторам, а не по тегам**. Теги остаются
основой и человеческой разметкой, вектор добавляет то, чего в разметке нет.

**Готово, когда:** запрос «квантовая гравитация и энтропия» находит статьи, где этих слов
нет, а смысл совпадает. Проверено вручную на десятке запросов.

**Стык от ML 2026-07-30: выгрузка готова, заливка за тобой.**

`python embeddings_export.py --archive <путь к lang/ru/archive>` → `data/embeddings-ours.jsonl`
(в git не едет, пересоздаётся за секунды). 2050 строк, 0 пропусков, по строке на статью:
`{id, text, namespace: "ours", metadata: {date, cat, express, title_ru, url, src}}`.

- **Размерность индекса 1024**, метрика cosine, namespace `ours` и `arxiv`. Namespace
  обязателен: 2000 наших статей утонут среди 3 млн абстрактов arXiv, и бот начнёт
  отвечать по чужому — это нарушение правила про ссылку на **нашу** статью.
- **Фактическую размерность ответа `@cf/baai/bge-m3` подтверди первым же вызовом** —
  в документации CF она не указана, 1024 взято из спецификации модели.
- **Наш индекс влезает в бесплатный тариф Vectorize**: 2050 × 1024 = 2,1 млн хранимых
  измерений из 5 млн бесплатных. Платный нужен для arXiv, а не для нас — весь контур
  бота можно собрать и померить за ноль.
- Пакет upsert: 1000 из Worker, 5000 по HTTP API.
- **Мелочь про дубль правил:** `data/embeddings-*.jsonl` добавлено в `.gitignore`.
  Список публикации в `cloudflare/deploy_r2.py` повторяет `.gitignore` вручную —
  проверь, не нужно ли зеркалить (папка не в git, отсюда не вижу).

**Метаданные согласованы (круг 3):** `title_en`, `date`, `has_full` — обязательные;
плюс `cat`, `title_ru`, `url`, `src`. `has_full=false` у экспрессов и потом у чужих
абстрактов arXiv — по нему бот отличает «есть полный разбор» от «есть только аннотация».

**Прогон мерки — что от тебя нужно, когда индекс поднимется.**

Набор готов и заморожен: `data/search-eval-queries.jsonl`, 800 строк
(100 статей × 4 языка × 2 вида запроса). Стоимость прогона — $0,0002 на эмбеддинг
запросов и 819k запрошенных измерений, то есть в пределах бесплатного.

1. Прогнать каждую строку через `/api/search`: `namespace = ours`, `topK = 10`.
2. Отдать один файл `results.json`: `{"<qid>": ["<id1>", "<id2>", ...]}` — id статей
   по убыванию релевантности, ключ `qid` брать из набора без изменений.
3. Я считаю: `python search_eval.py score --results results.json` → recall@1/5/10
   и MRR в разрезах по языку, виду запроса и полные/экспресс.

**Что этот прогон решает.** Индекс английский, запросы на четырёх языках. Требование
владельца «нашёл по-русски английский абстракт» до сих пор ничем не подтверждено —
разница recall между `en` и `ru`/`es`/`ar` и есть цена мультиязычности. Если она
окажется большой, схему запроса придётся менять (перевод запроса вместо прямого
мультиязычного вектора), и лучше узнать это до заливки arXiv, а не после.

### Ритуал ежедневной дозаливки

`embeddings_export.py --since ГГГГ-ММ-ДД --out data/embeddings-delta.jsonl` — готово,
проверено: за 28–30 июля отдаёт 9 статей вместо 2084.

**Порядок:** после `run.py daily` — дельта за вчера, upsert в namespace `ours`. Всё.

- **Отбор по дате статьи, а не по времени файла.** Пересборка HTML трогает все файлы,
  но статьи не меняет; по mtime мы бы каждый день перезаливали весь архив и платили
  за это. По дате — только новое.
- **Повторная заливка безопасна:** upsert в Vectorize идёт по id, повтор перезаписывает
  ту же запись. Пропущенный день добирается расширением `--since`, дублей не будет.
- **Стоимость дня:** 20 статей ≈ 5 тысяч токенов ≈ $0,00006. Ноль.

**Почему это ритуал, а не разовая заливка.** За сегодня архив вырос 2050 → 2066 → 2084,
пока мы разговаривали. Батч раз в неделю означает, что свежие статьи — те самые, ради
которых читатель и пришёл — неделю не находятся.

### Промпт и контур `/api/ask`

Промпт: `data/prompts/ask-answer.txt`. Три решения к нему, они мои по задаче:

**1. Контекст из top-5 — на языке читателя, без перевода на лету.** У нас есть
`abstract.<lang>.advanced` на всех четырёх языках. Для ответа бота переводить нечего:
берём готовый текст на языке вопроса, английский — только если языка нет. Перевод
на лету нужен поиску (заголовки в выдаче), но не боту.

Формат блока на каждый источник:

    [<id>] <title на языке читателя>
    <abstract.<lang>.advanced, до 1200 знаков>

Пять источников ≈ 6 тысяч знаков ≈ 1,5 тысячи токенов на вопрос. Это и есть главный
рычаг цены: десять источников вместо пяти удваивают стоимость каждого ответа.

**2. Порог «в базе нет» — 0,60 по лучшему результату, как стартовое значение.**
Настройкой, не в коде. Честно: на живом поиске я видел разброс 0,583–0,694 всего
на двух запросах, этого мало. **Правильный порог выведется из прогона 800** — мерка
даёт распределение score отдельно для верных и неверных попаданий, и порог берётся
там, где они расходятся. До прогона 0,60 — это заглушка, а не решение.

**3. Проверка ссылок — кодом, не промптом.** Промпт требует пометку `[id]` у каждого
утверждения, но модель нарушит инструкцию тем чаще, чем интереснее вопрос. Поэтому
после ответа:

- все `[id]` из ответа обязаны быть среди найденных — чужой id значит выдумку;
- ответ без единого `[id]` не отдаём вовсе, отдаём «в базе нет».

Это не перестраховка: правило «ответ без ссылки не показываем» либо держится
конструкцией, либо не держится никак.

## 6. Где живёт ежедневный автомат

Задача владельца: каждый день добирать по 20 свежих статей автоматически.

Команда уже есть, придумывать нечего:

```
python run.py daily --limit 20 --category "astro-ph.*,gr-qc,hep-th,quant-ph"
```

Это **не** пересборка сайта: `daily` забирает день с arXiv, ранжирует кандидатов единым
пулом по всем указанным разделам, генерирует топ-20 в несколько потоков, пишет их страницы
и пересчитывает агрегаты. Часовой прогон — это `html`, другая команда. Обложки для статей
берутся из PDF и ничего не стоят; платная генерация картинок осталась только для тегов
и законов.

**Почему всё же не Cloudflare.** Worker — это JavaScript в песочнице без файловой системы.
Наш конвейер на Python, и главное — ему нужно **состояние**: какие статьи уже есть, чтобы
не сделать дубль, реестры тегов, законов и учёных, шаблоны. Это тысячи файлов на диске,
а не пара запросов. Cloudflare Cron умеет **дёрнуть** что-то по расписанию — выполнять
работу должна машина с данными.

**А вот сторожем Cloudflare быть обязан.** Запуск по расписанию раз в сутки: посмотреть дату
последней статьи в ленте и, если свежее двух суток ничего нет, написать нам. Это ровно тот
отказ, который мы уже пропустили — сайт три дня отдавал старое, и никто не заметил.
Дешёво, в пределах бесплатного, и закрывает главный риск любого автомата: он молча встал.

Варианты, по возрастанию надёжности:

1. **Как сейчас** — задание в планировщике Windows на машине владельца. Работает, стоит ноль,
   но привязано к тому, что машина включена, и мы это уже теряли.
2. **Небольшой постоянный сервер** — пять-десять долларов в месяц, работает всегда, состояние
   лежит там же.
3. **GitHub Actions** — бесплатно и по расписанию, но **заблокировано задачей 00**: исходные
   данные не в git, автомату негде их взять. Класть их обратно в git нельзя — именно это
   убило прежний хостинг.

**Готово, когда:** выбран вариант, ежедневный прогон идёт сам, и о сбое мы узнаём не через
неделю по пустой ленте. Три дня простоя прошлым разом никто не заметил.

## 8. Вход: живьём проверить не смог, а по коду — три дыры в защите платных путей (QA, круг 2)

**Сначала честно: пункт «вход живьём» я НЕ закрыл.** Все шесть запросов к
`bridge42worlds.academy` из питон-клиента получили Cloudflare **1010 «Access denied»** —
режет не API, а сам клиент по признакам браузера. Браузер в моей песочнице наружу не пускают.
Подделывать признаки браузера, чтобы обойти бот-защиту, я не стал. Значит «анонимная норма
отдаётся до вопроса», «Turnstile отбивает запрос без проверки» и «заказ анонимом отклоняется
по норме» с моей стороны **не подтверждены** — по нашему же правилу «смёржено — не проверка»
это не «принято». Прогони четыре запроса сам и приложи вывод, либо скажи, как мне попасть
внутрь периметра.

Заодно вопрос: 1010 на `/api/*` для не-браузерного клиента — это намеренно? Если да, стоит
записать: любой программный клиент к нашему же API (мобильное приложение, скрипт, интеграция)
получит 403. Если нет — правило WAF стоит сузить, чтобы оно не накрывало `/api/`.

**Что видно по коду — и всё три про деньги.**

**8а. Turnstile открыт настежь, если секрет не задан.** `cloudflare/worker.js:203` —
`if (!env.TURNSTILE_SECRET) return true;` с комментарием «не настроено — не блокируем вход».
Сейчас секрет на месте, и всё хорошо. Но при переносе окружения, переименовании переменной
или выкладке в новое окружение защита от ботов **молча выключится**: ошибки нет, в журнале
пусто, снаружи всё работает. Это ровно наш способ ломаться — тихий откат — только в слое,
который стоит денег. Безопаснее наоборот: нет секрета → отказ и громкая запись в журнал.

**8б. Turnstile проверяется ровно в одном месте — и это единственный путь, который сейчас
не работает.** `turnstileOk` вызывается только из `handleCodeRequest` (worker.js:313), то есть
на запросе кода по почте, а он отвечает `mail_not_configured`. Ни `/api/order` (заказ статьи,
стоит 10), ни `/api/tutor` (вопрос модели, платный вызов) его не проверяют. Твоя же задача 0
говорит: «Turnstile на вход **и на будущую кнопку "хочу статью"»**.

**8в. Норма обходится подстановкой cookie.** `sessionId()` (worker.js:127) берёт `b42s`
из заголовка по одному лишь формату `[A-Za-z0-9]{8,64}` — ни подписи, ни проверки, что этот
номер выдавали мы. Дальше `uid = "s:" + sid`, и счётчик нормы висит на этом uid. Значит скрипт,
присылающий каждый раз новый случайный `b42s`, каждый раз получает свежую анонимную норму 3.
Для честного браузера норма работает, для скрипта её нет.

**Почему это «важно», а не «блокер»:** предохранитель на месте — `dayProject` (worker.js:66)
ограничивает проект 2000 в сутки по умолчанию, так что худший случай упирается в потолок,
а не в тысячи долларов. И 1010, который поймал я, показывает, что край всё-таки отбивает
наивный скрипт. Но защита не должна держаться на том, что WAF случайно оказался строг.

**Готово, когда:** 8а — отсутствие секрета даёт отказ, а не проход; 8б — Turnstile проверяется
на `/api/order` и `/api/tutor`; 8в — `b42s` подписан (HMAC на секрете Worker) или сверяется
с KV, и подменённый номер не открывает новую норму. Плюс вывод четырёх живых запросов
из первого абзаца.

## 7. Схема очереди: пять дыр в логике (от QA, круг 1, 07-30)

Читал `cloudflare/schema-queue.sql` — только читал, ничего не запускал. Решение «одна таблица
на троих» и набор полей выглядят правильно; `priority` и `attempts`, заведённые сразу, —
это как раз то, что потом не добавить. Ниже то, что видно как дыры, по убыванию цены.

**7а. Дедуп защищает от одновременных заказов, но не от повторных.** Уникальный индекс частичный:
`WHERE status IN ('queued','running')`. Значит после `done` тот же `dedupe_key` разрешён снова.
Для `ask` это верно, а для `translate` — нет: перевод статьи на арабский уже существует,
и десять человек, попросивших его завтра, оплатят десять прогонов модели. Проверять надо не
только очередь, но и «уже сделано»: либо не чистить ключ у `done`, либо перед постановкой
смотреть, есть ли готовый результат.

**7б. Нет ограничений на `status` и `kind`.** SQLite `CHECK` поддерживает. Сейчас опечатка
`'Done'` или `'queued '` пройдёт молча, и заказ навсегда выпадет из выборки исполнителя —
он ходит по `status`. Читатель будет вечно видеть «готовится», в логах ни одной ошибки.
Наш любимый способ сломаться: снаружи цело, внутри пусто.

**7в. Зависший `running` некому подобрать.** Если исполнитель умер после того, как поставил
`running`, заказ висит навсегда: `attempts` не растёт (его увеличивает исполнитель),
таймаута нет, индекса по `(status, started_at)` для поиска протухших тоже нет. Нужен и
критерий «висит дольше N минут», и способ его быстро найти.

**7г. Не описано, когда списывается `cost`.** Если при выполнении — очередь можно набить
бесплатно и упереться в потолок проекта чужими заказами. Если при постановке — при `failed`
и `rejected` нужен возврат, а поля или статуса для возврата в схеме нет. Это надо решить
до первого читателя, потом миграция.

**7д. `dedupe_key` для `article` — «нормализованная тема», то есть свободный текст.**
«чёрные дыры», «черные дыры» и «Чёрные дыры!» дадут три разных ключа и три оплаченных заказа.
Либо нормализация описана жёстко (регистр, ё/е, пунктуация, пробелы), либо склейка по теме
не работает.

**Готово, когда:** на каждый пункт есть решение в схеме или сознательный ответ «так задумано,
потому что…» в комментарии рядом — там же, где уже объяснено, почему таблица одна.

цена, которую можно проспать.

Число на читателя пересмотрим, когда появится учёт токенов; общий потолок — когда увидим
