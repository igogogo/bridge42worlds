## Решения владельца (зафиксированы)

1. **Экспресс-статьи не переводим.** Плашка «не переведено» уже честная, ленты чужих
   языков их не показывают — ничего не ломается.
2. **Новые языки — с даты включения.** Архив не догоняем массово.
3. **Доперевод — по запросу**: читатель хочет статью на своём языке → кнопка → очередь →
   перевод за минуту. ТА ЖЕ технология, что «хочу статью» (сборка D спринта 2):
   одна очередь, один воркер, один экран ожидания. Это делает добавление языка
   почти бесплатным: платим только за то, что реально читают.

## Объём работ (почему отдельный спринт)

- Промпты: combo-промпт в бой (+advanced остаётся как есть), правки simple/popular
  промптов не нужны — они уходят из ежедневного пути
- generate.py: build_article на конструктор (структура data.json НЕ меняется —
  те же поля popular/simple/mini, меняется способ наполнения; это ключ к безопасности)
- Переводы: translate-путь с дедупом общих полей + агент translate_flash для тиров,
  pro — для advanced; glossary — решить перевод (находка 0г промпт-инженера)
- Валидатор: доучить под slim-переводы (общие поля приходят переведёнными извне)
- Откат: флаг constructor в config.json, выключил — старый путь
- Приёмка: партия 10 статей старым путём против 10 новым, вслепую у контент-менеджера,
  QA по таблице; только потом включение по умолчанию
- Языковой слой: fr с даты X (решение при открытии спринта), «перевод по запросу»
  делит инфраструктуру со сборкой D спринта 2 — их правильно делать рядом
