Скопируй человеку его блок целиком. Каждый блок самодостаточен: с чего начать,
что делать, на что смотреть. Составлено 2026-07-29.

Общее для всех, если человек новый: репозиторий → README.md → ПРАВИЛА-РАБОТЫ.md →
свой файл в задачи/. Работать в своей папке: `git worktree add ../b42-<роль> -b <ветка>`.
В главную папку не заходить. Отчёт — в `задачи/отчёты/<роль>.md`, новая запись сверху.

## → DevOps  (ты — самый блокирующий человек спринта, начинай первым)

Твой файл: `задачи/devops.md`. Порядок: (1) авторизация — вход через Google (OAuth)
плюс почта+код, счётчики лимитов в KV, норма настройкой, остаток виден читателю
ДО вопроса, общий потолок на проект, Cloudflare Turnstile на вход; (2) **КАРКАС
ОЧЕРЕДИ в D1** — новость дня: очередь обслуживает ТРОИХ — бота (/api/ask),
кнопку «хочу эту статью» и кнопку «переведи на мой язык». Один каркас: заказ →
проверка токена и лимита → строка в D1 → воркер на нашей машине исполняет →
статус готовности. Спроектируй поля/статусы/приоритеты сразу под три типа заказов
и опиши схему письменно в отчёте — по ней пойдут разработчик и ML. Ничего ИИ-шного
не открывать до готовности лимитов — решение владельца. Ключи только секретами.

## → ML-инженер

Твой файл: `задачи/ml.md` — там же мой письменный ответ по графу: замер со-встречаемости
одобрен, делай. Главное спринта: мозги исследовательского бота — схема «вопрос → поиск
по вектору → отбор пассажей → ответ со ссылками на наши статьи», параметры (сколько
статей в контекст, какие поля, как ранжировать) и мерка качества: набор вопросов
с известными ответами, прогон до и после каждой правки, результат числом. Правило
проекта: ответ без ссылки на нашу статью не показываем — лучше честное «в базе нет».
Стык с DevOps: ты даёшь промпт и параметры, он исполняет в Worker.

## → Разработчик

Твой файл: `задачи/разработчик.md`. Два фронта: (1) единый поиск по ТЗ-ПОИСК.md —
можно начинать сейчас, формат ответа делай подменяемым, источник скоро станет сетевым;
(2) интерфейс бота, когда DevOps поднимет /api/ask: диалог, ответы со ссылками-карточками,
остаток лимита виден ДО отправки вопроса, честное пустое состояние. С телефона в первую
очередь, все языки, арабский RTL. На что смотреть: язык страницы, а не язык по умолчанию,
в каждой ссылке — этот класс бага у нас повторялся.

## → Дизайнер

Твой файл: `задачи/дизайн.md`. Спринт 2: (1) вид диалога бота в брендстиле, в паре
с разработчиком — вопрос/ответ, карточки-ссылки, индикатор остатка, пустое состояние;

из 20 статей разных наук глаз не теряется. Помни шкалу касания: минимум 44 пикселя,
она теперь общая, страховка в CSS есть, но новые элементы проверяй на 375.

## → Контент-менеджер  (второй по срочности — твой вердикт включает новый конвейер)

Твой файл: `задачи/контент.md`. ГЛАВНОЕ СЕЙЧАС — слепая приёмка «Конвейера 2.0»:
мы перестроили генерацию (три уровня одним вызовом, дешёвая модель на переводах
тиров) и статья подешевела втрое. Тебе дадут ~10 статей старого конвейера и ~10
нового ВПЕРЕМЕШКУ, без пометок. Оцени каждую по трём осям (стиль/полнота/уместность)

конвейер включается по умолчанию. Отдельно смотри: метафора ЕДИНА между уровнями
одной статьи (новый конвейер обещает это по построению); уровни различимы; в en/es
нет следов кальки. Формат находки: id · ось · что не так · цитата.
