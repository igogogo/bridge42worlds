# Спринт 2 — сообщение каждому в команде

Скопируй человеку его блок целиком. Каждый блок самодостаточен: с чего начать,
что делать, на что смотреть. Составлено 2026-07-29.

Общее для всех, если человек новый: репозиторий → README.md → ПРАВИЛА-РАБОТЫ.md →
свой файл в задачи/. Работать в своей папке: `git worktree add ../b42-<роль> -b <ветка>`.
В главную папку не заходить. Отчёт — в `задачи/отчёты/<роль>.md`, новая запись сверху.

## → DevOps

Твой файл: `задачи/devops.md`. Спринт 2: достроить авторизацию (задача 0 — вход по
одноразовому коду, счётчики в KV, норма настройкой, остаток виден читателю, общий
потолок), затем контур бота `/api/ask` (задача 1): токен → лимит → Vectorize → модель →
ответ со ссылками → списание. Схему ответа и промпт даёт ML-инженер — стык письменно
через отчёты. На что смотреть: у Cloudflare нет жёсткого потолка расхода — предохранитель
обязан быть в нашем коде; ключи только секретами Worker, в страницах их нет. Ничего
ИИ-шного не открывать до готовности лимитов — решение владельца.

## → ML-инженер

Твой файл: `задачи/ml.md` — там же мой письменный ответ по графу: замер со-встречаемости
одобрен, делай. Главное спринта: мозги исследовательского бота — схема «вопрос → поиск
по вектору → отбор пассажей → ответ со ссылками на наши статьи», параметры (сколько
статей в контекст, какие поля, как ранжировать) и мерка качества: набор вопросов
с известными ответами, прогон до и после каждой правки, результат числом. Правило
проекта: ответ без ссылки на нашу статью не показываем — лучше честное «в базе нет».
Стык с DevOps: ты даёшь промпт и параметры, он исполняет в Worker.

## → Разработчик

Твой файл: `задачи/разработчик.md`. Два фронта: (1) единый поиск по ТЗ-ПОИСК.md —
можно начинать сейчас, формат ответа делай подменяемым, источник скоро станет сетевым;
(2) интерфейс бота, когда DevOps поднимет /api/ask: диалог, ответы со ссылками-карточками,
остаток лимита виден ДО отправки вопроса, честное пустое состояние. С телефона в первую
очередь, все языки, арабский RTL. На что смотреть: язык страницы, а не язык по умолчанию,
в каждой ссылке — этот класс бага у нас повторялся.

## → Дизайнер

Твой файл: `задачи/дизайн.md`. Спринт 2: (1) вид диалога бота в брендстиле, в паре
с разработчиком — вопрос/ответ, карточки-ссылки, индикатор остатка, пустое состояние;
(2) решение по карточкам новых доменов — лента станет разнообразной (биомед, инженерия,
информатика): нужен ли домену цветовой акцент или единый стиль важнее; критерий — в ленте
из 20 статей разных наук глаз не теряется. Помни шкалу касания: минимум 44 пикселя,
она теперь общая, страховка в CSS есть, но новые элементы проверяй на 375.

## → Промпт-инженер

Твой файл: `задачи/промпты.md`. Главное спринта: доменные словари тегов — периметр
расширяется на всю науку (биомед, инженерия, информатика), словарь на домен, статья
выбирает облако по своим разделам arXiv. Инструменты: tags_watch.py и накопленные
предложения модели. Второе: стиль на «не-физике» — промпты писались под астрофизику,
прочитай первые 20 статей каждого нового домена; алкогольные аналогии под запретом
всегда. Третье: французский на подходе — проверь, что validate_translation ловит
русский-во-французском. Помни: словарь тегов ЗАКРЫТЫЙ, ре-тег без словаря разносит
облако — уже проходили на био-цикле.

## → Контент-менеджер

Твой файл: `задачи/контент.md` — роль новая, там всё подробно. Суть: читать
свежесгенерированные статьи глазами читателя и оценивать по трём осям — стиль
(живой язык? клише? уровни различимы?), полнота (ответ на вопрос заголовка, главное
число, все 4 уровня × 4 языка), уместность (отбор интересного, метафоры пригодны
для арабской аудитории, теги по делу). Первые партии — за вчера и позавчера, уже
генерируются. Формат находки: id · ось · что не так · цитата. Системное (повторяется
из статьи в статью) — отдельной строкой в задачи промпт-инженеру: это его вход.

и информация как физика — реально недостающие.
