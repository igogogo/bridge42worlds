# Формат данных наблюдательного совета

Одно заседание — один файл `data/council/<ГГГГ-ММ-ДД>.json`. Страницы архива строит
`council_build.py`; руками HTML не пишем.

Почему JSON, а не база: заседаний десятки в год, они меняются редко, и их надо
**видеть в истории правок** — кто что поправил в протоколе и когда. База это скрывает,
git показывает. Предложения от людей будут приходить в хранилище через приёмник
(задача DevOps), а сюда попадают уже сведёнными в повестку — это разные вещи и разные
сроки жизни.

## Схема

```json
{
  "date": "2026-08-04",
  "number": 1,
  "status": "план | идёт | закрыто",
  "opened": "Короткая рамка: с чем пришли на это заседание.",

  "agenda": [
    {
      "id": "a1",
      "title": "Заголовок вопроса — одной строкой, человеческим языком",
      "body": "Суть: что предлагается и почему это вообще вопрос.",
      "from": ["B42-XXXX", "Игорь"],
      "merged": ["исходная формулировка 1", "исходная формулировка 2"],
      "options": ["За", "Против", "Отложить"],
      "votes": { "За": 3, "Против": 1, "Отложить": 0 },
      "decision": "принято | отклонено | отложено",
      "why": "Почему решили так. У отклонённого — обязательно.",
      "outcome": "Что из этого вышло. Заполняется после спринта, не сразу."
    }
  ],

  "sprint": {
    "from": "2026-08-04", "to": "2026-08-10",
    "planned": ["Что берём в работу по итогам голосования"],
    "done": ["Что реально сделано — собирается из истории правок"],
    "carried": ["Что не успели и переносим"]
  },

  "next": ["Вопросы, которые уже видно в следующую повестку"]
}
```

## Правила, которые делают это механизмом, а не отпиской

**Отклонённое остаётся видимым.** Поле `why` у отклонённого обязательно. Предложение,
исчезнувшее без объяснения, — самый быстрый способ отучить людей предлагать.

**Решение связано со спринтом.** Принятое обязано попасть в `sprint.planned`, а потом
в `outcome`. Проголосовали и не сделали — доверие уходит быстрее, чем от прямого отказа.

**Модель сводит, но не отбирает.** `council_digest.py` объединяет одинаковое, отсекает
уже сделанное и приводит формулировки в порядок. Решать по существу — только
голосованием: иначе модель тихо отфильтрует неудобное, и мы этого не заметим.

**Авторство сохраняется.** В `from` — ключ участника или имя. В `merged` — исходные
формулировки до сведения, чтобы человек узнал своё предложение в общей повестке.
