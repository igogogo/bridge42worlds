# Единый поиск по сайту — задание разработчику

Составлено 2026-07-29. Основание: поиск на страницах тега, закона и учёного непонятен —
поле стоит на карточке закона, а ищет по всем статьям сайта, и выглядит сломанным.
Плюс решение владельца: после переезда на Cloudflare мы не привязаны к статике и можем
строить поиск нормально.

Порядок работы — [ПРАВИЛА-РАБОТЫ.md](%D0%9F%D0%A0%D0%90%D0%92%D0%98%D0%9B%D0%90-%D0%A0%D0%90%D0%91%D0%9E%D0%A2%D0%AB.md).

---

## Что не так сейчас

**Одно поле делает разное на разных страницах.** В ленте оно фильтрует статьи — это понятно.
На странице закона оно тоже фильтрует все статьи сайта и подменяет ими список статей закона.
Читатель ждал поиска внутри закона, получил чужое, решил, что сломано.

**Ищется только по статьям.** Теги, законы, учёные и разделы в выдачу не попадают, хотя
у нас 363 тега, 145 законов, 201 учёный — и человек чаще ищет именно понятие, а не статью.

**Синтаксис знают не все.** Есть приставки `#тег`, `!учёный`, `@автор` — мощно, но угадать
их невозможно, подсказки появляются только если уже начал.

---

## Что делаем

Один поиск на весь сайт. Вводишь что угодно — получаешь ответ, разложенный по видам:

```
        Найдено: 34 статьи · 3 тега · 1 закон · 2 учёных

  ПОНЯТИЯ
    #аккреционный диск        142 статьи
    #чёрная дыра               89 статей
  ЗАКОНЫ
    Закон Кеплера              ↳ 12 статей
  УЧЁНЫЕ
    Иоганн Кеплер              1571–1630
  СТАТЬИ  (34)
    …карточки как в ленте…
```

Сначала понятия, потом статьи: если человек ищет «энтропия», ему скорее нужна карточка
понятия, а не тридцатая статья с этим словом.

### Два режима поиска, и разница видна глазом

**Общий** — по всему сайту. Открывается кнопкой поиска в шапке, доступен с любой страницы.

**Внутри раздела** — на странице тега, закона, учёного ищет **только по статьям этого
раздела**. Подпись в поле говорит прямо: «искать среди статей закона» вместо безликого
«Поиск…». Переключение на общий — ссылкой в выдаче: «искать по всему сайту →».

Это и есть ответ на вопрос «может, надо два поиска»: поиск один, но он знает, где стоит,
и честно об этом пишет.

## Как считать релевантность

Порядок внутри каждого вида — по убыванию совпадения:

1. точное совпадение названия;
2. название начинается с запроса;
3. запрос встречается в названии;
4. запрос встречается в описании (для статей — в заголовке и аннотации).

Внутри одинакового веса — по числу связанных статей (популярное выше), для статей — по дате.

Регистр не важен. Поиск должен работать по подстроке, а не по началу слова: «диск» обязан
находить «аккреционный диск».

**Язык.** Ищем по данным текущего языка. Плюс всегда проверяем латинский идентификатор:
человек может набрать `entropy` на русской версии, и это должно найти «энтропию».

## Откуда брать данные

Всё уже есть в готовых файлах, ничего генерировать заново не надо:

| Вид | Файл | Записей |
|---|---|---|
| Статьи | `lang/{lang}/articles-index.json` | 1980 |
| Понятия | `lang/{lang}/data/tags.json` | 363 |
| Законы | `lang/{lang}/data/laws.json` | 145 |
| Учёные | `lang/{lang}/data/scientists.json` | 201 |
| Разделы | `data/arxiv-categories.json` | 156 |

**Важно про вес.** Индекс статей — 5,9 МБ, теги — 4,4 МБ. Тянуть это ради поиска нельзя:
на телефоне это секунды ожидания и лишний трафик. Нужен **отдельный лёгкий индекс поиска**
— только то, по чему ищем и что показываем в строке результата:

```json
{"t":"tag","id":"accretion_disk","n":"аккреционный диск","c":142}
{"t":"law","id":"kepler_laws","n":"Законы Кеплера","c":12}
{"t":"sci","id":"Johannes_Kepler","n":"Иоганн Кеплер","s":"1571–1630"}
{"t":"art","id":"2607.00742","n":"Заголовок статьи","d":"2026-07-01"}
```

Собирать в конце генерации, класть в `lang/{lang}/search-index.json`. Ожидаемый размер —
меньше 400 КБ, это уже приемлемо. Проверить фактический и записать в комментарий.

## Где это живёт: страница или Worker

**Начинать со статики.** Лёгкий индекс + поиск в браузере закрывает задачу целиком, работает
без сети после первой загрузки и ничего не стоит. Тысячи записей фильтруются мгновенно.

**Worker понадобится позже**, когда захотим: опечатки («энтропыя» → «энтропия»), поиск по
телу статей, а не только по заголовкам, подсказки по частоте запросов. Тогда индекс уезжает
в KV или D1, а страница ходит в `/api/search?q=`. Закладывать это сейчас не надо, но
**формат ответа выбрать сразу такой, чтобы источник можно было подменить** — страница не
должна знать, откуда пришли результаты.

---

## Что должно получиться

- [ ] Скрипт сборки лёгкого индекса, шагом в конце генерации
- [ ] Поиск ищет по всем видам, выдача сгруппирована и озаглавлена числами
- [ ] На странице тега, закона, учёного — поиск внутри раздела, подпись поля это объясняет
- [ ] Из выдачи внутри раздела есть переход к общему поиску
- [ ] Приставки `#`, `!`, `@` продолжают работать для тех, кто привык
- [ ] Работает на четырёх языках, в арабском не ломает раскладку
- [ ] На телефоне поле не открывается пустым «непонятно что вводить» — в нём подсказка
      с примером, а под ним три-четыре популярных понятия как быстрый вход
- [ ] Пустой результат объясняет, что делать: «ничего не нашлось — попробуйте по-другому
      или посмотрите все понятия»

## Чего не делать

- Не тянуть в браузер полный индекс статей ради поиска.
- Не заводить второе поле рядом с первым: путаницу лечим подписью и группировкой, а не
  удвоением элементов.
- Не менять адреса страниц: поиск — это слой поверх, а не новая структура.
