# Работы не из arXiv: приём

Владелец 11.09.2026: «у нас появился опыт инкапсулирования статей не из архива. Там было
много проблем, которые мы собирали руками, и это разные источники — они могут быть не PDF.
Давай такую попытку: ты сам ищешь в сети свежее и интересное».

Первая такая работа — `2609.90001`, разбор OpenAI о взрыве в уравнениях Навье–Стокса.
Она делалась целиком руками: пять языковых модулей, три уровня, сборщик, рисунки — сорок
тысяч строк на одну статью. Повторять это на каждую находку нельзя.

## Что изменилось

Разбор пишет **обычный конвейер**, как для любой работы с arXiv. Руками делается только
ПРИЁМ: найти первоисточник, снять метаданные, положить текст. Дальше `run.py ids <номер>`
и всё идёт своим чередом — уровни чтения, пять языков, разметка понятиями, вектор, карточки.

Так вышло потому, что у конвейера нашлась ровно одна дверь: `fetch_one_arxiv()` сперва
смотрит в нашу локальную базу метаданных и только потом идёт в сеть. Работа, положенная
в эту базу, для конвейера неотличима от любой другой — менять генератор не понадобилось.

## Как это работает

1. **Запись источника** — `tools/outside/works/<номер>.json`. Лежит в `tools/`, а не в
   `data/`: `data/` публикуется целиком, рабочим файлам там не место.
2. **Номер** — свой, из хвоста `YYMM.900NN`. Формат нужен генератору (из номера выводится
   месяц), а `900xx` на arXiv не бывает — по номеру сразу видно, что работа наша.
3. **Полный текст** — `fulltext.txt` в папке статьи. Если он есть, генератор берёт текст
   с диска и за PDF не идёт вовсе. Это и решает «источники могут быть не PDF»: HTML-страница,
   препринт, технический отчёт — что угодно, лишь бы текст удалось снять.
4. **Лицензия** — по адресу из записи, через `gen_arxiv.license_class()`. Класс `analysis`
   значит: пересказ наш, авторские рисунки и абстракт не показываем.

## Приём

Запись готовит тот, кто читал страницу источника — человек или агент. Разбирать чужую
вёрстку кодом не пробуем: издателей десятки, у каждого своя, и надёжнее прочитать глазами.

```bash
python tools/outside/intake.py заготовка.json          # проверить и показать, что будет
python tools/outside/intake.py заготовка.json --apply  # завести работу
python run.py ids 2609.90002                           # обычный разбор
```

Заготовка — обычный JSON:

```json
{
  "title": "Название работы как у источника",
  "authors": ["Фамилия И.", "..."],
  "date": "2026-08-20",
  "abstract": "Аннотация ДОСЛОВНО со страницы источника",
  "url": "https://...",
  "pdf": "https://...",
  "doi": "10.1038/...",
  "org": "Nature Aging",
  "licence_url": "https://creativecommons.org/licenses/by/4.0/",
  "categories": ["q-bio.CB", "q-bio.MN"],
  "fulltext": "необязательно: текст работы, если снят со страницы"
}
```

Обязательны: `title`, `date`, `abstract`, `url`, `licence_url`, `categories`.
`pdf` — если дан, текст снимается с него; иначе берётся `fulltext`; иначе остаётся одна
аннотация, и приём об этом честно предупреждает.

## bioRxiv и medRxiv: сбор машиной

Владелец 12.09.2026: «меня интересует тот источник биотех архив по насыщению, по работам,
связанным с омоложением и прочей этой тематикой». И следом: «бери 8».

У препринт-серверов bioRxiv и medRxiv вёрстку читать глазами не нужно — у них есть
машинный вход, который отдаёт сразу всё: заголовок, авторов, DOI, рубрику, лицензию и
полную аннотацию. Поэтому заготовку тут собирает код, а дверь остаётся прежней: сборщик
зовёт тот же `intake.py` и не повторяет ни присвоения номера, ни проверки на повтор, ни
пола по лицензии.

```bash
python tools/outside/biorxiv.py --days 7                        # показать, что нашлось
python tools/outside/biorxiv.py --days 1 --limit 8 --apply      # завести дневную порцию
python tools/outside/biorxiv.py --days 1 --apply --generate     # завести и сразу разобрать
```

Шагом `biorxiv` он стоит в дневном конвейере сразу за днями arXiv — до насыщения знаниями,
иначе принятая работа не успела бы ни на разметку, ни на понятия, ни на граф.

### Что замерено

Неделя 10–16.08.2026, 772 препринта: у сервера ~110 работ в сутки, ядро темы старения —
54 за неделю, то есть **~8 в сутки и ~2800 в год**. Рубрик ровно 25, список закрытый.
Лицензии ядра: свободных около трети, остальное идёт нашим пересказом.

### Три вещи, на которых это ломается

1. **Рубрики — не косметика.** В `vector_select.py` нижние 20% по близости к нашему
   корпусу режутся ДО промпта, а обход этого среза смотрит на `primary_category`. У
   bioRxiv кодов arXiv нет вовсе — там «cell biology» словами. Работы про старение от
   нашего физического корпуса дальше всего, так что без таблицы перевода весь поток
   вырезался бы молча, ещё до модели. Поэтому `categories[0]` всегда валидный `q-bio.*`.

2. **`aging` сидит внутри `imaging`.** Первый замер по подстрокам дал 17% темы и двадцать
   «понятий про старение» в реестре — и то и другое оказалось мусором: ловились `imaging`,
   `packaging`, `averaging`. По границам слов честные числа — 7% и ноль. Разница втрое.

3. **`cc_no` — это не пустое поле.** У сервера это известное состояние прав («все права
   защищены»), а `intake` пустой адрес читает как забытый и работу отбивает. Так молча
   отваливалась бы каждая четвёртая. Адрес ведёт на страницу условий сервера, класс —
   «только пересказ».

### Отбор

Работа проходит, только если у неё есть **сильное** слово (`senescence`, `lifespan`,
`telomere`, `longevity`, `rejuvenation`…). Одного `reprogramming` или `age-related` мало:
перепрограммирование клеток бывает и вне геронтологии, а `age-related` цепляет любую
возрастную выборку. Слабые слова только добавляют веса при сортировке; заголовок весит
втрое против аннотации.

Что уже предлагалось, помнит `biorxiv-seen.json` — повторно то же не возьмём.

### Полный текст

Из `jatsxml`, а не из PDF: размеченные разделы вместо вытряхивания, 200 КБ вместо 39 МБ.
Список литературы и служебные блоки выкидываются. Сервер отдаёт полный текст только со
своим `User-Agent` — голому запросу приходит 403, хотя сам API отвечает и ему.

### Зачем это нужно было

В корпусе 7286 работ, из них `q-bio` — 3,3%, а клеточной биологии девять штук. В реестре
понятий 3627 со статьями, преимущественно биологических 117, про старение — **ни одного**.
Это не поломка реестра: понятия растут ИЗ разобранных статей, и сочинять словарь руками
нельзя — получим термины, под которыми нет работ. Насыщение идёт отсюда.

## Чего тут нет

Сборщика «своей работы» с рисунками и блоком машины знаний — это отдельная история, она
живёт в `tools/ownworks/` и нужна, когда разбор пишется руками. Здесь работа проходит как
обычная: наш пересказ по её тексту.
