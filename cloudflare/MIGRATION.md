# Переезд bridge42worlds: GitHub Pages → Cloudflare (R2 + Worker)

Подготовлено 2026-07-24. **Пока НЕ активно** — ждём аккаунт Cloudflare + токен.
Причина: рост ×100 за ~месяц; Pages упирается в 1 ГБ / лимит файлов / часовые git-пуши.
Cloudflare Pages не подходит (лимит 20 000 файлов на деплой, у нас уже ~28k) → R2 + Worker.

## Что делает ТЫ (разово, ~30–60 мин; Claude ведёт за руку)

1. Завести аккаунт **Cloudflare** (бесплатно).
2. Add site → `bridge42worlds.academy`. Cloudflare выдаст **2 nameservers**.
3. У регистратора домена заменить nameservers на выданные (2 поля). *(SEO не страдает — домен и URL те же.)*
4. Привязать карту (R2/Workers ~$5–20/мес).
5. Создать **API-токен** (права: Workers Scripts:Edit, Workers R2 Storage:Edit) → отдать Claude.
   Отдельно: **R2 → Manage API tokens** → создать S3-ключи (R2_ACCESS_KEY_ID / SECRET) для delta-деплоя.

## Что делает Claude (командами, wrangler/boto3)

- `wrangler r2 bucket create bridge42worlds-site`
- Первичная заливка сайта в R2 (`deploy_r2.py`, зальёт всё; потом — только дельту).
- Деплой Worker (`wrangler deploy`) — роутер из `worker.js`.
- Тест на `*.workers.dev` или `beta.bridge42worlds.academy` (проверить: главная, статья все языки,
  дашборд, поиск, лайки, sitemap, 404, редирект www→apex).
- После проверки — привязать маршрут apex (раскомментить `routes` в `wrangler.toml`), `wrangler deploy`.
- Обновить `.gitignore`: перестать трекать собранный HTML/картинки (git = только код + data.json).
- В пайплайн генерации добавить финальный шаг: `python cloudflare/deploy_r2.py` вместо git-push HTML.

## Файлы (готовы)

- `wrangler.toml` — проект Worker + привязка R2.
- `worker.js` — роутер: R2-статика, www→apex, чистые URL, 404, кэш (картинки год immutable, HTML 5 мин), 304.
- `deploy_r2.py` — delta-деплой: заливает только изменённые файлы (md5-манифест `.r2-manifest.json`),
  параллельно, с content-type. Заменяет 20-мин git-push. `--prune` чистит удалённые.

## Фазы (низкий риск, ноль простоя)

- **Ф0.** Перестать трекать собранный HTML в git (после Ф2, иначе Pages нечего отдавать).
- **Ф1.** R2-бакет + Worker, тест на поддомене (DNS ещё на старом → ничего не ломается).
- **Ф2.** Delta-деплой из генератора (тут исчезает боль часовых пушей).
- **Ф3 (опц.).** Индекс статей → D1/KV на краю: клиент не качает 3.6 МБ JSON, поиск на edge.
- **Ф4 (опц.).** likes/views/feedback → Worker + D1, уход с Supabase. *(Сначала Supabase НЕ трогаем.)*
- **Ф5.** DNS apex → Worker, GitHub Pages выводим.

## Стоимость (порядок)

R2 хранение ~$0.15–0.5/мес (7–15 ГБ), **egress бесплатный**; Workers free до 100k/день, далее $5/мес
за 10M запросов. Итого **~$5–20/мес**, масштаб до 100×.

## SEO / риски

- URL и домен те же → индексация Google сохраняется. Sitemap+hreflang у нас есть.
- Перенос nameservers: несколько часов распространения, сайт работает как обычно (Cloudflare проксирует
  на старый origin, пока не переключим). Ноль простоя.
- Откат: вернуть nameservers/маршрут на Pages — мгновенно.

## Открытые вопросы к обсуждению завтра

- Supabase оставляем (рекомендация: да, на Ф1–Ф2 не трогаем).
- Нужен ли сразу edge-индекс (Ф3) или позже, когда реально пойдёт трафик.
