# Бот-тьютор: как протестировать локально и как выкатить

Бот живёт в том же Worker'е, что и статика (`cloudflare/worker.js`), маршруты:
- `POST /api/tutor` — вопрос ученика → ответ DeepSeek (роль тьютора, рамки, режим подсказки);
- `POST /api/tutor/issue` — выдать токен доступа (нужен `x-admin-key`).

## 1. Локальный тест БЕЗ ключа (уже работает)

Ничего не нужно: страница `course-thermodynamics.html` открывается с обычного статик-сервера,
бот отвечает **заготовленными подсказками из JSON** и честно помечает это демо-режимом.

```bash
python -m http.server 8123
```
→ `http://localhost:8123/course-thermodynamics.html`

## 2. Локальный тест С живым DeepSeek

Нужен Node и ключ DeepSeek (тот же, которым генерируются статьи).

**Шаг 1.** Положить ключ в `cloudflare/.dev.vars` (файл НЕ коммитить, он уже под .gitignore-правилом ниже):

```
DEEPSEEK_API_KEY=sk-ваш-ключ
ADMIN_KEY=любая-строка-для-выдачи-токенов
```

**Шаг 2.** Поднять Worker:

```bash
cd cloudflare && npx wrangler dev --port 8787
```

**Шаг 3.** Сказать странице, куда ходить (Worker на другом порту, поэтому явно):
в `course-thermodynamics.html` перед подключением `tutor.js` добавить строку

```html
<script>window.B42_TUTOR_API = 'http://localhost:8787/api/tutor';</script>
```

CORS для этого случая в Worker'е уже прописан. Токен локально не требуется —
гейт включается только когда привязан KV (см. ниже).

## 3. Прод (Cloudflare)

Миграция сайта на R2+Worker уже подготовлена (см. `MIGRATION.md`) — бот едет тем же деплоем.

```bash
# 1. Хранилище токенов и корпуса вопросов
wrangler kv namespace create TUTOR_TOKENS
# → раскомментировать [[kv_namespaces]] в wrangler.toml и вставить id

# 2. Секреты (в репозиторий не попадают)
wrangler secret put DEEPSEEK_API_KEY
wrangler secret put ADMIN_KEY

# 3. Деплой
wrangler deploy
```

### Выдать токен ученику (на неделю)

```bash
curl -X POST https://<worker>/api/tutor/issue \
  -H "x-admin-key: <ADMIN_KEY>" -H "content-type: application/json" \
  -d '{"days":7,"limitTotal":200,"limitDay":50,"note":"демо для университета"}'
```

Ответ: `{"token":"...","expires":...}`. Токен можно передать ссылкой —
`https://сайт/course-thermodynamics.html?token=ВЫДАННЫЙ_ТОКЕН` — страница сама его запомнит
и уберёт из адресной строки.

## Защита от «выноса» по расходу — что уже стоит

| Уровень | Ограничение |
|---|---|
| Токен | живёт N дней (по умолчанию 7), без него в проде бот не отвечает |
| Токен | не более 200 вопросов всего и 50 в сутки (настраивается при выдаче) |
| Сессия | 10 вопросов/подсказок на одну сессию чтения (в `tutor.js`) |
| Запрос | вопрос обрезается до 600 символов на фронте и 1200 на сервере, контекст — до 4000 |
| Ответ | `max_tokens: 400` — длинные простыни не генерируются |

## Корпус вопросов (учимся на обучении)

Каждая пара «вопрос → ответ» пишется в KV ключом `qa:<timestamp>:<id>` на 90 дней:
язык, режим (`ask`/`hint`), тема раздела, текст вопроса и ответа. Персональных данных нет.

Выгрузить и посмотреть, на чём чаще всего спотыкаются:

```bash
wrangler kv key list --binding TOKENS --prefix "qa:" > questions.json
```

Дальше из этого собираются «частые вопросы» прямо в статью — и видно, какие места в материале
объяснены плохо (если по одному абзацу приходит поток вопросов — переписывать надо абзац, а не ученика).
